# Research: ADF v1.1 against the 2026 agent platform

> Cited findings from a multi-source deep-research pass (June 2026). 22 primary sources, 25 claims
> adversarially verified (3-vote, 0 refuted). This is the evidence base for `docs/roadmap.md` and
> ADRs 0007–0009. Each finding names its source; do not cargo-cult — see Caveats.

## Verdict

ADF's CLAUDE.md + skills + agents + hooks architecture is **valid and well-aligned** with
Anthropic's published guidance, but its concrete Claude Code wiring is **minimal** and behind
current platform capabilities. Every improvement below is additive — nothing in v0.1.0 is broken.

## Findings

### Platform mechanics (Claude Code 2026)

1. **Subagent frontmatter is richer than ADF uses.** `model` accepts `sonnet|opus|haiku|fable`, a
   full model ID, or `inherit` (default); `tools` allowlist OR `disallowedTools` denylist, both
   accepting `mcp__<server>` / `mcp__<server>__*` patterns; plus `permissionMode`, `maxTurns`,
   `skills` preload, `mcpServers`, `hooks`, `memory`, `background`, `effort`, `isolation: worktree`,
   `color`, `initialPrompt`. ADF pins all 11 agents to `model: inherit` and exact tool names only.
   — sub-agents doc.
2. **Skills follow the open Agent Skills standard** (agentskills.io). SKILL.md supports
   `allowed-tools`, `disallowed-tools`, `model`, `effort`, `context: fork` (native isolated-subagent
   run — no conversation history), `agent`, `hooks`, `paths`, `when_to_use`, `argument-hint`,
   `arguments`, `disable-model-invocation`, `user-invocable`. ADF skills use only `name`+`description`
   (which remains valid). — skills doc, agentskills.io.
3. **Skills can be benchmarked** with the official `skill-creator` plugin: spawns an isolated
   subagent per test case, grades to `grading.json`, aggregates pass-rate / time / tokens (with vs
   without skill) to `benchmark.json`. ADF has no eval mechanism. — skills doc, skill-creator blog.
4. **Hooks ADF omits map exactly onto its memory gap.** `PreCompact` (fires before compaction, can
   block), `PostCompact`, `SessionEnd` (matchers clear/resume/logout/prompt_input_exit),
   `UserPromptSubmit` (can block via exit 2 and inject context), `SubagentStart/Stop`. ADF wires
   only SessionStart / PreToolUse(Edit|Write) / Stop. — hooks doc, plugins-reference (~30 events).
5. **Output styles** modify the system prompt every turn (distinct from CLAUDE.md, agents, skills);
   portable Markdown, shippable inside plugins. ADF uses none. — output-styles doc.
6. **First-class plugin + marketplace system.** One plugin bundles skills, agents, hooks, MCP/LSP
   servers via `.claude-plugin/plugin.json` (only `name` required; component path fields + semver
   `version` + `dependencies`); `.claude-plugin/marketplace.json` at repo root makes it
   `claude plugin install <plugin>@<marketplace>` with `update`/scopes. Docs include a
   "convert .claude/ configurations to plugins" walkthrough. Highest-leverage packaging change.
   — plugins-reference, plugin-marketplaces, anthropics/claude-code marketplace.json.

### Anthropic agent-engineering guidance

7. **Context engineering validates `adf-memory/`.** Compaction distills a near-full window
   (preserve architectural decisions + unresolved bugs, discard redundant tool output) and
   reinitializes; structured note-taking persists notes outside context and pulls them back. A
   file-based memory tool shipped (Sonnet 4.5, public beta). — effective-context-engineering,
   news/context-management.
8. **Long-running harnesses: compaction alone is insufficient.** Durable external state — a
   progress file + git history + `init.sh` — is needed to reconstruct state across fresh windows;
   scope work to one feature per session ending in a clean, mergeable state. ADF's one-loop-one-commit
   + `loops/NNNN-slug.md` already align; make the progress-file + clean-state gate explicit.
   — effective-harnesses-for-long-running-agents, cwc-long-running-agents.
9. **Multi-agent orchestration discipline.** Orchestrator-worker: lead delegates to 3–5 parallel
   subagents with isolated context (compression), each returning a ~1,000–2,000 token summary;
   every subagent needs an explicit objective, output format, tool/source guidance, and task
   boundaries; scale effort to complexity. ADF should add summary-size budgets + a delegation-contract
   template. — multi-agent-research-system, effective-context-engineering.

## Open questions (unresolved by this pass)

- **AGENTS.md** (now stewarded by the Agentic AI Foundation under the Linux Foundation, 60k+ repos,
  25+ tools) and spec-driven dev (spec-kit, OpenSpec) were searched but no claim survived synthesis
  (budget-dropped). ADF being CLAUDE.md-only is a portability risk — **needs a dedicated follow-up.**
- Submodule (exFAT copy-fallback) vs plugin: does the plugin path cover ADF's portability cases?
  Needs an exFAT test before fully migrating off the submodule.
- Reconcile "AI Score advisory-never-a-gate" with real `benchmark.json` pass-rate/token/time data.
- Which agents warrant non-inherit model tiers / which review skills should run `context: fork` —
  needs a per-agent cost/quality benchmark first.

## Caveats (stale-format risk)

- Docs migrated `docs.claude.com` → `code.claude.com` (301); cite the canonical `code.claude.com`.
- The standalone `/output-style` command was deprecated v2.1.73, removed v2.1.91 — select via
  `/config` or the `outputStyle` setting; file format unaffected.
- Plugin `monitors`/`themes` live under an experimental manifest key; rely only on the stable
  skills/agents/hooks/mcpServers surface for migration.
- `context: fork`/`agent` via the Skill tool had a bug (GitHub #17283, now closed) — verify isolation
  on the target Claude Code version before depending on it.
- The multi-agent ~90% speedup is research/parallel-exploration-scoped with ~15× token cost and
  weaker fit for tightly-interdependent coding — do not apply universally to ADF's implementation loops.
